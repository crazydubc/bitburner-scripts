# Go opponents selected for current goals

**Board-size follow-up:** [The measured fixed profile](2026-10-20-go-board-profile.md) now supplies the default board sizes. Optional `--board-size auto` uses time to the remaining rewards during a funded favor route; its ordinary learning policy remains available.

`go.js` now defaults to `--opponent auto`. It finishes the current game, records the result, reads current work/economy state, and chooses the next opponent. The log explains the goal and the board-size decision. Move priorities are unchanged.

| Situation | Preferred benefit |
| --- | --- |
| Crime work | Slum Snakes for success, balanced with Tetrads for combat levels. A known near-capped crime chance reduces the value of more success bonuses. |
| Gym training | Tetrads. |
| Faction or company work | Daedalus, whose bonus improves both reputation multipliers. |
| Cash below the reserve or the $1m early cash cushion | Netburners if Hacknet is a material cash source; otherwise The Black Hand, balanced with Illuminati. |
| General hacking progress | The Black Hand / Illuminati; the hidden opponent becomes eligible for hacking-level progress after installing The Red Pill. |
| A close, funded donation unlock | The relevant joined Go faction can take priority over ordinary bonus farming. |

Within useful alternatives, selection discounts an already-large bonus and uses the existing strategy/cheat/bonus-time cohort's reliability evidence. These weights are heuristics, not a proven global optimum. Ordinary opponent comparisons require twelve timed samples before using their measured reliability. Existing per-opponent board-size learning, fixed-size options, and protection against experimenting during a winning streak remain. Switching opponents after a completed game preserves each opponent's separate streak.

Hacknet must have positive production. Hash servers count as a cash source only when a running `spend-hashes.js` is configured to sell for money and capacity can hold a sale. Detection includes offloaded sellers. The selector never redirects hashes. Hacknet cash must be at least 10% of the since-install hacking-income average to receive the cash priority; stock gains are excluded from that average. BN8's disabled cash sources are excluded. Instant production versus a historical hacking average is an approximation, especially during rapid batcher growth.

## Donation favor

Go awards favor directly for every second consecutive win against a faction you have joined. This differs from ordinary faction work: reputation from work converts into favor on installation. Current faction favor, not projected post-install favor, determines whether Go can unlock donations immediately.

The faction manager publishes a quote for a useful, still reputation-locked ordinary augmentation, including its purchase price and the remaining reputation donation bill. Already-owned prerequisites are required; unmet chains, redundant providers, gang factions, omitted augmentations, and factions without donations do not justify the route. Current cash **above the live reserve** must cover the whole quote. Stock value alone does not pass this check, and the selector does not spend anything.

For an available Go opponent, the policy converts the remaining favor gap to its reputation-equivalent amount, checks the remaining per-faction Go reward cap, and estimates time using the selected board's recent complete games. It uses a conservative win-probability estimate, accounts for losses breaking a streak and an odd positive streak being one win from a reward, and requires at least four timed samples in the matching cohort. There is no invented time forecast for unmeasured boards. The effective SF14 level determines reward size and cap; the installed Red Pill does not affect favor rewards.

An unlock must fit within fifteen minutes. Once chosen, its deadline cannot slide forward on refresh; an expired route is skipped for the rest of this Go process's current installation. Funds, useful purchases, reward cap, and ETA are rechecked after each completed game. Favor earned since the manager's snapshot is subtracted so an already-reached threshold does not get chased again. Board experiments are paused while pursuing this measured route. Restarting Go restarts this in-memory attempt budget.

The policy does not change the faction worker's chosen work, delay augmentation installations, buy reputation, or force a faction invitation. Non-Go factions such as CyberSec cannot receive direct Go favor; Daedalus remains useful when working their reputation. This is opponent allocation within the existing progression flow.

## Usage and low-RAM behavior

Pull `testing/bn1-go-audit`, including the new `bin/go-context.js`, then stop the existing Go process and launch the updated home copy, or let autopilot relaunch it:

```text
home
run git-pull.js --branch testing/bn1-go-audit
run go.js --opponent auto
```

If `go.js.config.txt` explicitly sets `"opponent": "random"` or a faction, change that setting to `"auto"` to enable this policy. Other existing settings remain applicable. Let an old faction-manager pass finish; its next updated run publishes the favor quotes. Go keeps playing if quotes are unavailable.

Before SF4, the current-work API is unavailable. Automatic economy/hacking fallback still works, and the user can state the current goal explicitly:

```text
run go.js --opponent auto --goal rep
run go.js --opponent auto --goal crime
run go.js --opponent auto --goal combat
run go.js --opponent auto --goal money
run go.js --opponent auto --goal hacking
```

Stop the existing Go process before changing launch arguments, or edit the corresponding config keys before restarting. `--goal auto` resumes inference. A manual `rep` goal still considers funded favor unlocks; other manual goals bypass that priority. An explicit `--opponent "Daedalus"`, `--opponent random`, or `--opponent hidden` overrides goal selection entirely. The hidden opponent retains its installed-Red-Pill gate and mandatory 19x19 board.

One read-only 6.6 GB helper runs on home between games. Optional Singularity reads use their effective SF4 RAM costs and are skipped if they cannot fit. The bot remains **3.5 GB**. Missing helpers, stale/corrupt state, unavailable API access, and RAM shortages fall back to playing; they do not stop the player action or interrupt a board. Worker hints require a live PID and matching reset identifiers. Favor quotes expire after ninety seconds.
