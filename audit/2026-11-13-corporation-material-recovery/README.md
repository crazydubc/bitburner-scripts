A normal purchase reports success; an interrupted order whose cleanup succeeded reports a skipped phase. No positive booster order is replayed. The manager continues with the same funding review. Real API, validation and cleanup errors remain errors. If the separate zero-rate clear batch reports the specific early-exit sentinel, the manager repeats only the cancellation once and skips that phase.
- Use the 3.0.1 material API's `buyAmount`. The old fixture supplied an extra `desiredBuyAmount` property which does not exist in the game. This matters for divisions that use a booster as a recipe input, such as Hardware in Water Utilities. Four-field buy requests from older managers still restore to zero; new requests also carry the underlying input rate.
- In round two, when there is a real, unaffordable setup expense or an empty Tobacco product slot, protect a share of available cash for it. Use actual prices and the existing reserves. At most once per observed earning cycle, set aside half of the cash still uncommitted after outstanding bills, planned inputs and the operating cushion. The rest remains available for growth. The first blocked expansion has priority; full-lineup replacement is not a savings goal. The corporation log shows the goal and amount set aside.
